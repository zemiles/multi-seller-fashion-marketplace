# v1 전체 로직 요구사항

기준일: 2026-09-21 · 요구사항 버전: 1.0 · 대상: 모의 결제 멀티셀러 패션 마켓플레이스.

사용자 요청은 “앞으로 로직에 대한 요구사항을 미리 만들고, PG는 현재 두 개에 연결”하는 것입니다. 이 문서 묶음은 그 요청에 따라 **구현할 v1 기준을 결정한 명세**입니다. 새로 정한 기간·금액·인증 방식은 과거 대화에서 사용자가 개별 승인한 내용이 아니라 이번에 구체화한 프로젝트 기본 정책입니다. 구현 시 다시 선택할 공백으로 남기지 않습니다. 변경하려면 결정 ID와 영향받는 계약·테스트를 함께 변경합니다.

문서 작성은 기능 구현 완료를 의미하지 않습니다. 현재 코드 상태는 [BACKEND_DESIGN](../BACKEND_DESIGN.md), 실행 방법은 [MSA](../../MSA.md)가 기준입니다. 이번 변경은 문서와 목표 계약에 한정하며 실행 코드·기존 DB를 변경하지 않습니다.

## 읽는 순서와 책임

2026-09-22 상세화: [구현 상세 문서 6종](../implementation/README.md)을 추가했습니다. 이 요구사항을 바꾸는 별도 설계가 아니라 transaction/lock·typed event·backfill·화면·복구를 구체화한 구현 기준입니다. [추적표](../implementation/04-traceability.md)에서 55개 요구사항의 연결과 미구현/계약 보완 상태를 확인합니다. netAmount의 DB 매핑, 부분 역전, 은행 대사, 승인 상태의 구체적인 전환은 [MIG-02](../implementation/03-migrations.md)가 정합니다.

정책을 실제 필드·관계로 확인할 때는 [테이블 ERD·데이터 사전](../erd/README.md)과 [API 명세서](../api/README.md)를 함께 읽습니다. 현재 물리 정의/현재 PG API와 v1 목표 모델·계약은 별도로 표시합니다.

## 역할과 기능 범위

| 역할 | 필수 업무 |
| --- | --- |
| 비로그인 방문자 | 판매중 상품·공개 리뷰·검색 조회, 가입/로그인 |
| 회원 | 프로필/주소/찜/장바구니, checkout/결제, 주문·배송, 취소/반품/교환/확정, 후기/알림 |
| 판매자 OWNER | 입점·문서·계좌·팀·상품·재고·배송·Claim·정산 조회 |
| 판매자 CATALOG/FULFILLMENT/FINANCE | 각각 부여된 업무만, 다른 판매자 접근 불가 |
| 관리자 SUPPORT/CATALOG/RISK/FINANCE/IAM | 역할별 조회·검수·승인·분쟁·대사·계정 관리, 변경 감사 |
| 배치/서비스 | 전용 principal/scope로 만료·복구·이벤트·정산 처리. 일반 관리자 우회 권한 없음 |

소유 테이블이 존재하는 기능은 아래 상세 명세로 처리합니다. 물리 테이블의 모든 enum이나 확장 칼럼을 v1 기능으로 노출하는 것은 아닙니다. CHARGEBACK, AUTHORIZE/CAPTURE 분리, 현금영수증, 외부 신용결제, 다중 통화, 쿠폰/포인트, 차액 교환, 실은행 송금은 명시적 v1 제외 기능입니다.

## 구현자 작업 규칙

1. 해당 요구사항 ID, 선행 기능, 상태 전이, 오류·권한·멱등 조건과 [수용 테스트](08-delivery-acceptance.md)를 읽습니다.
2. 현재 코드에 없으면 “미구현”으로 작업합니다. 결정되어 있는 정책을 다시 미정으로 돌리지 않습니다.
3. 정책값은 서버 설정/버전 있는 정책으로 관리하고 주문·정산 snapshot에는 적용 버전을 저장합니다. 환경별로 통화·돈 계산·멱등 의미를 바꾸지 않습니다.
4. HTTP DTO/OpenAPI·migration·서비스 로직·테스트·구현 현황을 함께 갱신합니다. 이미 적용된 migration과 과거 거래 snapshot은 덮어쓰지 않습니다.
5. 실제 공급자/실결제 전환은 별도 요구사항 변경입니다. 현재 문서만으로 실제 금전 이동이나 공개 서비스 배포를 승인하지 않습니다.
